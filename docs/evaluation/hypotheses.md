# Hypothesis loop evaluation

Generated by `python -m aegisflow_dr.hypotheses_eval` (development, validation and held-out (`--include-heldout`)).

**Scope.** Deterministic hypothesis bookkeeping against simulated mechanisms injected into generated series. Simulated mechanisms only, written by the same authors as the catalog: no real sensors, no root cause, no model, no live agent, no production connection.

Every investigation record carries the fixed statement: "Candidate mechanisms consistent with fixed probes on these measurements. Not a root-cause determination."

## Corpus

60 generated groups (groups 60-119) from the baseline evaluation's generator (`baseline_eval`: `ts` every 60 s, `temp_c` = one seasonal wave with amplitude A in {1, 3} plus Gaussian noise, `pressure_kpa` = N(100, 1), `flow_lpm` = N(5, 1)). The baseline is built from 3 reference batches of 400 records; the current batch is the next 400 records with one scenario injected. Injections are seeded per group and scenario. `as_of` is the latest current timestamp + 60 s unless the scenario says otherwise.

The corpus is disjoint from the baseline comparison evaluation (D05c, groups 0-59): the generator is seeded by the group number, so no group, base series or payload is shared with it. Every investigation starts with `baseline.compare`, whose checks were developed on those groups, so reusing them would have measured the observation layer on data it was developed on. An earlier draft of this evaluation reused groups 0-59; this was corrected before the held-out split was scored.

Groups are split by a hash of the group number (salt `aegisflow-hypotheses-eval-v1`, buckets 6/2/2 out of 10), realized as development 30, validation 18 and held-out 12 groups; all scenarios of a group stay in one split. Held-out is small, so its intervals are wide: a perfect 12/12 has a Wilson 95% lower bound of 75.8%.

| Scenario | Injection | Expected hypothesis (mechanism/column) |
|---|---|---|

| duplicate_delivery | 400 records, then records 0-299 again (exact duplicate rows) | duplicate_delivery/(no column) |
| delivery_delay | complete batch, as_of = latest + 1,800 s | delivery_delay/(no column) |
| source_outage | only the first 160 records, as_of = time of the 400th record + 60 s | source_outage/(no column) |
| field_outage | flow_lpm empty in one contiguous run of 100 records starting at a seeded record in [50, 250] | field_outage/flow_lpm |
| intermittent_loss | flow_lpm empty in 100 seeded scattered records | intermittent_loss/flow_lpm |
| clean | none | none |
| unmodelled_sign_flip | pressure_kpa x -1 | none |
| unmodelled_amplitude | temp_c seasonal amplitude 1 <-> 3 swapped (same phase and noise) | none |

Per case (one per group): *truth supported* — the expected hypothesis is supported; *truth only supported* — it is the only supported hypothesis; *truth refuted* — a probe refuted it; *other mechanism supported* — any other hypothesis except `genuine_change` is supported (wrong support). For `clean` and the unmodelled scenarios: *any hypothesis* — at least one hypothesis was generated; *misattributed* — any catalog mechanism other than `genuine_change` is supported. Rates are `count/cases = percent [95% Wilson interval]`; `n/a` means the metric does not apply to the scenario or there was nothing to measure.

## Probe thresholds

Every probe threshold and the probe budget (`max_probes = 6`) are fixed in `docs/superpowers/specs/2026-11-24-hypothesis-contracts-design.md` (sections "Probes" and "Bounded loop and replanning"), written before any measurement. No threshold was changed in response to these numbers.

## Reading these numbers

- Simulated mechanisms only, written by the same authors as the catalog and its probes. Success on modelled scenarios measures internal consistency (the probes recognise the injections they were designed around), not real-world diagnosis; there are no real sensors and no labelled real incidents.
- The two unmodelled scenarios (`unmodelled_sign_flip`, `unmodelled_amplitude`) are changes outside the catalog. They measure misattribution for these two changes only: how often the loop supports a catalog mechanism for these two hand-picked changes outside the catalog; it is not a misattribution rate for unmodelled changes in general.
- Intervals cover variation between generated groups only. Injection sizes are fixed and far from every threshold (no magnitude sweep), so near-ceiling rates show that the probes recognise these injections, not how well they detect smaller or different ones; the sign-flip misattribution is structural: it follows from the probe rules and would hold for any group, so it is not a sampling estimate.
- Probes assume one mechanism acts on a column at a time, and every case injects one mechanism into one column. Combined changes (for example an offset plus extra noise) can refute every candidate, the true ones included, and with several shifted columns the default budget of 6 can be spent before every column is probed (a unit change across six columns ends `none_supported`). None of this is measured here.
- `genuine_change` (a real change in the measured process) cannot be tested from these data: no probe supports or refutes it, so it stays open whenever it is generated, and these numbers say nothing about it.
- "Supported" means consistent with fixed probes and inconsistent with none on these measurements. There is no root cause, no model, no live agent and no production connection.
- A `resolved` stop or a `single_supported` verdict does not mean the supported hypothesis is correct. On development and validation the unmodelled sign flip ends `resolved` with `calibration_offset` as the only supported hypothesis: the loop settles confidently on a wrong mechanism when the true change is outside the catalog.
- `clean` produces no observations at all on development and validation (stop reason `no_observations`), so no hypothesis is ever generated for it there. Its *any hypothesis* rate is therefore not evidence of a low false-support rate: clean never tests false support of a hypothesis.
- Replanning adds nothing measurable on this corpus. On development and validation no scenario used more than 3 of the 6 probes, and during development a fixed probe order with statuses settled once at the end gave the same truth and wrong-support results, only with more probes. The "replanning disabled" mutant is exposed only because it also removes status updates.
- `stuck_sensor` co-supports `calibration_offset` on `temp_c` in some development and validation cases, which lowers its *truth only supported* rate: the stuck run moves the mean by at least half a baseline sd while the spread ratio stays inside the offset band of `spread_ratio`.
- Read the *other supported hypotheses* column with the probe rules: a stuck run moves the mean while the standard deviation can stay inside the `calibration_offset` band of `spread_ratio`, so both can be supported together; a sign flip keeps the spread and moves the mean by many baseline sd, which is what `spread_ratio` reads as a calibration offset; a larger seasonal amplitude raises the spread without moving the mean, which is what it reads as a noise increase. These are limits of the fixed probes, not tuned away.
- One case per group, groups generated independently; scenarios of the same group share one baseline, so rates across scenarios are not independent of each other.
- Thresholds are not changed after the held-out split is scored; anything held-out reveals is reported as a weakness.
