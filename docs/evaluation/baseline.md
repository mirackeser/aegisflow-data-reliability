# Baseline comparison evaluation

Generated by `python -m aegisflow_dr.baseline_eval` (development and validation; `--include-heldout` adds the held-out split).

**Scope.** Deterministic baseline comparison against synthetic changes in generated series. Synthetic generated series only: no real sensors, change kinds chosen by the authors of the checks, no root cause, no model, no production connection.

## Corpus

60 generated groups, split by a hash of the group number into development, validation and held-out; all variants of a group stay in one split. Each group is one process: `ts` every 60 s from 2026-01-01T00:00:00, `temp_c` = 20 + A sin(2π i/100 + φ) + N(0, σ) with A in {1, 3} and σ in {0.2, 0.5}, `pressure_kpa` = N(100, 1), `flow_lpm` = N(5, 1), three decimals. The baseline is built from 3 consecutive reference batches of 400 records; the current batch is the next 400 records with one variant applied. `as_of` is the latest current timestamp + 60 s unless the variant says otherwise.

The hash buckets are 6/2/2 out of 10, realized as development 37, validation 14 and held-out 9 groups. Held-out is small, so its intervals are wide: a perfect 9/9 has a Wilson 95% lower bound of 70.1%.

| Variant | Change | Truth (keys that must be found) |
|---|---|---|
| clean | none | none |
| clean_partial_cycle | current batch has 350 records | none |
| clean_jitter | every current timestamp moved by an integer U(-10, 10) s, order kept | none |
| clean_recent_lag | as_of = latest + 150 s (inside the 180 s SLA) | none |

| unit_change | pressure_kpa x 10 | distribution_shift/pressure_kpa |
| sampling_slow | interval 120 s, 400 records | sampling_interval_change/ts |
| sampling_fast | interval 30 s, 400 records | sampling_interval_change/ts |

| volume_spike | 1,000 records | volume_change/None |
| stale | as_of = latest + 1,800 s | freshness/ts |
| null_increase | 25% of flow_lpm cells emptied | empty_rate_change/flow_lpm |

A case is *detected* when every truth key is found, and has an *unexpected finding* when any found key is not in its truth. Rates are `found/total = percent [95% Wilson interval]`; `n/a` means there was nothing to measure.

## Thresholds and where they came from

- `PSI_SHIFT = 0.25`: the conventional "significant population shift" rule of thumb in credit-risk practice, chosen before any measurement. PSI uses the baseline decile bins with 0.5 added to every bin count on both sides.
- `SAMPLING_RATIO = 1.5` and `VOLUME_RATIO = 1.5`, a freshness SLA of `FRESHNESS_INTERVALS = 3` baseline sampling intervals, and `EMPTY_RATE_DELTA = 0.1`: design choices written in the design document, not fitted.
- `MIN_VALUES = 150`: the fewest numeric values for baseline decile edges and for a PSI comparison. With no change, E[PSI] ≈ (B − 1)(1/n_baseline + 1/n_current) with B = 10 bins; requiring the current-size term (B − 1)/n_current ≤ PSI_SHIFT / 4 gives n_current ≥ 144, rounded to 150. It was set before the held-out split was scored, after an independent reviewer's null simulation showed P(PSI > 0.25) ≈ 0.20 at the earlier minimum of 50 values.
- No threshold was changed in response to these numbers.

No-change PSI (seeded, uses no corpus group): i.i.d. N(0, 1) current batches against a fresh 1,200-value i.i.d. N(0, 1) baseline per draw, binned on the baseline deciles exactly as `compare` does.

## Reading these numbers

- Synthetic generated series only; no real sensors. Every change kind was chosen by the authors of the checks, and the large kinds were sized to be found. High scores mean the checks do what they were written to do on this one family of series; they are not evidence about real sensors, heavier-tailed noise or other change kinds.
- PSI is a descriptive index, not a significance test. On autocorrelated series it has no p-value, and a batch that covers a different part of a seasonal cycle can move it without any change in the process.
- Fewer records raise PSI sampling noise on every column, the i.i.d. ones included (see the no-change PSI table above). Partial seasonal cycles add a further shift on `temp_c`: `clean_partial_cycle` (350 records, 3.5 cycles) and `volume_drop` (160 records, 1.6 cycles) deliver less than whole seasonal cycles, while the baseline holds whole ones. A resulting `distribution_shift` is counted as an unexpected finding.
- Per-variant case rates count one case per group, and groups are generated independently. Per-check key rates pool keys across the 14 variants of a group: keys from the same group are correlated (they share one generated process and one baseline), so the per-check Wilson intervals, which treat them as independent, are optimistic; case-level rates are the more conservative reading.
- Small mean shifts (0.25 baseline sd, `mean_shift_small`) are only partly detected by design: the PSI threshold is fixed and was not lowered to catch them. The development sensitivity table above shows how detection grows with the size of the shift.
- Findings are fixed-rule differences from a stored baseline: no root cause, no model, no production connection.
- Thresholds are not changed after the held-out split is scored; anything held-out reveals is reported as a weakness.
