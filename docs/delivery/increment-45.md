# Increment 45 — Retained evaluation campaigns and integrated qualification

This package joins three related deliverables: a multi-case evaluation runner using actual retained investigation and bounded dispatch; crash-preserving campaign artifacts with read-only verified reporting; and operational/quality qualification through the signed pinned mTLS gateway. It adds a runnable installed CLI without enabling providers or interface work.

Raw model claims and independently accepted advice are scored separately. Aggregate cost/token limits carry across cases, unknown holds stop further dispatch, and omitted execution never shrinks the evaluation denominator. Public provenance stays unapproved and the statistical quality gate remains BLOCK even when every fixture passes operationally.

Validation: 794 application plus 13 security/hygiene methods, 807 distinct total, 23 new application methods. Python 3.12 and 3.14 full statement/branch coverage remains 100%, with no exclusions. Fourteen installed-package checks include the complete campaign through real temporary loopback mTLS. Tests cover wrong signed claims, invalid signatures, malformed/uncorrelated responses, abstention, budget/latency limits, actual process exit, concurrent launches, interrupted-run refusal, artifact tampering, frozen provenance and zero-call historical readback. Fresh dependency, secret and repository hygiene checks and exact-revision PR/main CI remain release requirements; final links belong to the delivery PR.

The source audit also verified that original architecture/PDF, existing test files and execution modules were not replaced. Original tests are retained; only the new campaign modules/tests and current documentation/CI are changed.

See [ADR-0045](../adr/0045-retained-evaluation-campaign.md) and [contract/runbook](../contracts/evaluation-campaign-v1.md).
