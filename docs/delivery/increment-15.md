# Increment 15 — Durable usage admission and accounting

Delivered: a separate SQLite usage ledger, frozen host limits, exact prepared-input/model/quote binding, integer token/cost reservations, shared original deadlines, bounded per-request attempts, hashed idempotency keys, atomic admission and one-shot start. Known settlement charges usage and releases unused holds. Ambiguous usage retains its full hold and blocks retry; crash/reopen does not reset accounting. Existing deterministic Judge authority is unchanged.

Measured locally on 2026-11-11: **374 application plus 13 security/hygiene methods = 387 distinct passing tests**. The 28 new tests cover exact/overflow limits, malformed inputs and databases, existing database preservation, clock rollback/expiry, idempotency conflicts, retry deadline/attempt limits, late and contradictory settlements, UNKNOWN recovery restrictions, concurrent admission/start, zero price/usage, prompt digest mutation and Judge independence. Usage code covers 160/160 statements and 50/50 branch exits; the full advisory package and existing critical coverage gates remain 100%.

The installed distribution is verified outside the checkout with a new accounting/reopen/duplicate-start check and all seven existing package checks. No dependency is added. Dependency auditing, candidate secret/file/PDF scanning and CI full-history scanning remain required release checks. Original architecture/PDF, evidence schemas, fingerprints and queue execution source are preserved.

Scope: local trusted-host admission, not live provider enforcement or measured model accuracy. Fixture counts/rates are not price estimates. The adapter must independently validate actual provider framing/tokenization/pricing and enforce transport deadlines/output caps. UNKNOWN reconciliation, account-wide quotas, retention and production operations remain future gates. See [ADR-0016](../adr/0016-durable-usage-admission.md) and [API/lifecycle contract](../contracts/usage-ledger-v1.md).

Next: an offline simulated provider-neutral dispatcher with typed adapter results, remaining-deadline/output-cap enforcement and deterministic retry/backoff tests. Explicit fallback must preserve a shared logical-operation budget across newly bound model requests. No provider/data residency/spending decision is needed for that offline increment; live activation and independent sealed evaluation remain gated. Interface work stays deferred.
